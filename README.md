# Haadthip Journey — Word to HTML Converter

เว็บภาษาไทยสำหรับแปลง **DOCX + รูปภาพที่แยกมา** เป็น HTML แบบ `<div class="mb-5">` และรูป WebP พร้อม Path `/storage/newsroom/haadthip-journey/{ปี}/{เดือน}/YYYYMMDD-HHMMSS-ลำดับ.webp`

## วิธีใช้งาน
1. เปิด `index.html` ด้วย **Chrome หรือ Edge รุ่นใหม่** (หาก Browser จำกัดการเข้าถึงไฟล์ ให้เปิดผ่าน Local Server)
2. เลือกไฟล์ ZIP ที่มี DOCX และ JPG/PNG อยู่ภายใน หรือเลือก DOCX และภาพแยกพร้อมกัน
3. กด **อ่านไฟล์และสร้างเนื้อหา**
4. เลือกปี/เดือนและตรวจการจับคู่รูปภาพ โดยสามารถกด **จับคู่ภาพจากความคล้ายกัน** หากรูปถูกเรียงไม่ตรงกัน และปรับจาก Dropdown รายภาพ
5. ตรวจแท็บ Preview, HTML Source และข้อความจาก Word
6. กด **คัดลอก HTML**, **ดาวน์โหลด HTML** หรือ **ดาวน์โหลด ZIP** เพื่อรับ HTML และไฟล์ WebP
7. อัปโหลดรูป WebP จาก ZIP ไปยัง `/storage/newsroom/haadthip-journey/{ปี}/{เดือน}/` บนระบบเว็บไซต์จริงด้วยตัวเอง

## ใช้ Local Server (ทางเลือก)
```bash
python -m http.server 8000
```
แล้วเข้า http://localhost:8000

## เผยแพร่บน GitHub Pages
1. สร้าง Repository ใหม่บน GitHub
2. อัปโหลด `index.html`, `styles.css`, `app.js`, `README.md`, `.gitignore`
3. Settings > Pages > Build and deployment > Deploy from a branch > `main` / root
4. เปิด URL ที่ GitHub Pages แสดง (HTTPS)

## กฎการทำงาน
- ไม่มี Backend, Database, Cookie, LocalStorage หรือการอัปโหลดข้อมูลไปยังเซิร์ฟเวอร์
- ใช้ Browser ZIP Parser, DOMParser สำหรับ DOCX, Canvas สำหรับ WebP และสร้าง ZIP แบบ Store (ไม่บีบอัดซ้ำ)
- รูปที่ใช้ส่งออกคือ JPG/PNG ที่แยกมา ไม่ใช่รูปฝัง Word (รูปฝัง Word ใช้ช่วยเปรียบเทียบลำดับเท่านั้น)
- รูปที่เลือกจะถูกใช้ซ้ำหรือขาดได้ในหน้า Preview แต่ระบบ **ปฏิเสธการ Export** หากขาดหรือเลือกซ้ำ
- ชื่อชุดรูปจะสร้างเมื่อเริ่มนำเข้าไฟล์ ใช้เวลาในเครื่องผู้ใช้ แล้วลำดับเริ่ม 1
- สคริปต์อ่านความสัมพันธ์ของรูปใน Word และรองรับย่อหน้า, bold, italic, underline, ตารางแบบพื้นฐาน
- ข้อมูลจะหายเมื่อ Refresh / ปิดแท็บ

## ข้อจำกัดที่ควรทราบ
- เอกสาร DOCX ที่ซับซ้อน (Text Box, SmartArt, หลายคอลัมน์, ภาพลอย, รูปจาก VML, เงื่อนไขพิเศษ) อาจต้องตรวจและปรับ HTML ด้วยตนเอง
- ฟิลเตอร์หน้าปก/บรีฟก่อนหัวข้อเป็น Heuristic อาจไม่ตรงทุก Word ต้องเช็กเนื้อหา
- ระบบใช้ `<div class="mb-5">` และ `<p>`, `<img>` ตามขอบเขตที่ตกลงกัน **ยังไม่อ้างว่าโครงสร้างย่อยตรง CMS จริง 100%** เพราะต้องมี HTML ตัวอย่างจาก Article Detail ที่ใช้ลงจริง
- ไม่สามารถยืนยันลิงก์หรืออัปโหลดรูปบนเว็บปลายทางจากเครื่องมือนี้ และไม่ได้ผูก CMS API
- การสร้างชื่อซ้ำข้ามการนำเข้าที่เกิดภายในวินาทีเดียวกันอาจเป็นไปได้เมื่อแปลงหลายงาน ให้ตรวจชื่อเดิมบนเซิร์ฟเวอร์ก่อนอัปโหลด
- ZIP และรูปใหญ่มากอาจใช้ RAM สูง โดยเฉพาะรูปต้นฉบับขนาดใหญ่หลายภาพ ควรใช้ Desktop Chrome/Edge

## นโยบายไฟล์
GitHub เก็บเฉพาะ Source Code ของโปรแกรม ผู้ใช้ต้องอัปโหลด Source Code และ Deploy ด้วยตนเอง; ระบบไม่ส่งหรือเก็บ Word/รูป/Output บน GitHub อัตโนมัติ


## กฎแบ่งเนื้อหาเป็น `div.mb-5` (ปรับปรุง)

- รูปภาพ 1 รูปที่เริ่มกลุ่ม ใช้ `<figure class="text-center mb-4">` พร้อม `img-fluid`
- รูปภาพตั้งแต่ 2 รูปที่อยู่ติดกันใน Word จะรวมเป็น Gallery ด้วย `row justify-content-center no-gutters mb-4` และ `col-md-*` ภายใน `div.mb-5` เดียว
- เนื้อหาหลังรูปจะอยู่ใน `div.mb-5` เดียวกับรูป จนกว่าจะพบรูปชุดใหม่หลังข้อความ แล้วจึงเปิด `div.mb-5` ใหม่
- ถ้ามีข้อความก่อนรูปแรก ระบบเก็บข้อความนั้นไว้หลังรูปแรกของกลุ่ม (หลังการกรองบรีฟที่เปิดใช้งาน)
- ย่อหน้าสุดท้ายของแต่ละกลุ่มใช้ `p.mb-0` และหัวข้อที่ตรวจพบใช้ `h5` หรือ `h6`
- ชื่อรูปภาพเริ่มลำดับที่ `0` เช่น `YYYYMMDD-HHMMSS-0.webp` และตรงกับไฟล์ WebP ภายใน ZIP
- โปรดตรวจการแยกหัวข้อและตำแหน่งรูปด้วย Preview โดยเฉพาะ Word ที่มีตารางหรือจัดวางรูปในรูปแบบพิเศษ

## การตั้งค่า Output เพิ่มเติม

- ไม่สร้างแท็ก `<em>` จากข้อความตัวเอียงใน Word แต่คงข้อความเดิมไว้
- ผู้ใช้เลือกความกว้างสูงสุดของภาพ WebP ได้ 500, 800, 1000 (ค่าเริ่มต้น), 1200, 1600, 1920 หรือ 2560 พิกเซล หรือเลือกขนาดเดิมโดยไม่ย่อภาพ ทุกตัวเลือกคงอัตราส่วนเดิม และจะไม่ขยายรูปที่มีขนาดเล็กกว่าที่เลือก
- ข้อกำหนดนี้มีผลกับไฟล์รูปใน ZIP ที่ส่งออก ไม่ใช่การแสดง Preview ภายในหน้าเว็บ
